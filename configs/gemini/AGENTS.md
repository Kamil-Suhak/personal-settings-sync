# Global Agent Guidelines

* **Git**: Use Conventional Commits without scope parens: `<type>: <description>` (`feat|fix|docs|refactor|chore|test|visual|ci|perf|build`, lowercase, imperative, max 72 chars, no trailing period). Never run `git push` without explicit approval.
* **No Inline Scripts**: Never pass loops, variables, functions, or multi-statement logic via `node -e`, `python -c`, `bash -c`, `zsh -c`, or `sh -c`. Write a script in `scratch/` and execute the file instead.
* **Archives & Binaries (`.docx`, `.xlsx`, `.zip`, `.sqlite`, `.pdf`)**: Use standard CLI tools (`tar`, `python -m zipfile`); if custom logic is needed, use `write_file` in your conversation `scratch/` directory and execute the script file.
* **Verification**: Run relevant tests, typechecks, and `git status`/`git diff`, iterating until checks pass. Never run `npm run dev`, long-running dev servers, or browser tests/screenshots unless asked.
* **Architecture (DRY/KISS & Anti-Glue)**: Keep code simple, flat, and free of duplicate logic or premature abstractions. Never bolt isolated patches onto code not designed for them—flag architectural tension and propose a refactor first.
* **Obsidian Vault as Source of Truth**: Project-specific rules, specs, plans, and architecture notes live in the active Obsidian vault's `wiki/` directory rather than per-repo `AGENTS.md` files. Check `wiki/Projects/<repo>/` when starting work in a repository, treat `raw/` as the user's unedited scratchpad (only distill `raw/` into `wiki/` when asked), and name each folder's hub note after its folder/topic (`<Topic>/<Topic>.md`) so graph nodes stay unambiguous.
* **Tooling & Environment Feedback**: If you hit genuine friction in tools, skills, permissions, environment, or docs structure during a task, append a brief 1–2 line `Tooling Note` at the end of your response (only when noteworthy; save deep audits for `/feedback`).
